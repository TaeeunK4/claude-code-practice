# PRD: TodoList 웹앱

## 배경 및 목적
할 일을 적고, 완료 여부를 표시하고, 지울 수 있는 가벼운 개인용 웹앱을 만든다. 설치나 빌드 없이 `index.html`을 브라우저로 열기만 하면 바로 사용할 수 있어야 하고, 새로고침하거나 브라우저를 다시 열어도 목록이 유지되어야 한다.

## 대상 사용자
- 자기 브라우저에서 혼자 할 일을 관리하는 개인 사용자 1명
- 여러 기기 간 동기화나 여러 사용자 공유는 고려하지 않는다

## 요구사항

### R1. 할 일 추가
- 입력창에 텍스트를 입력하고 **추가 버튼 클릭 또는 Enter**로 목록에 추가한다.
- 입력값은 앞뒤 공백을 제거(trim)한 뒤 저장한다.
- trim 결과가 빈 문자열이면(빈 입력, 공백만 입력) **추가하지 않고 조용히 무시**한다. 입력창 포커스는 유지한다.
- 추가에 성공하면 입력창을 비우고 포커스를 입력창에 둔다.
- 같은 텍스트의 중복 추가를 허용하고, 글자 수 제한은 두지 않는다.

### R2. 할 일 목록 표시
- 추가한 순서대로 표시하며, 새 항목은 **목록 맨 아래**에 붙는다.
- 각 항목은 완료 체크박스, 할 일 텍스트, 삭제 버튼으로 구성한다.
- 목록이 비어 있으면 "할 일이 없습니다" 안내 문구를 표시한다.
- 텍스트는 HTML로 해석하지 않고 입력한 문자 그대로 표시한다(`textContent` 사용).

### R3. 완료 체크/해제
- 체크박스를 클릭하면 완료/미완료가 토글된다.
- 완료된 항목은 텍스트에 취소선이 그어지고 흐리게 표시된다. 목록 내 위치는 바뀌지 않는다.

### R4. 삭제
- 삭제 버튼을 누르면 해당 항목 하나만 **확인창 없이 즉시** 삭제된다.
- 텍스트가 같은 항목이 여러 개 있어도 누른 항목만 삭제된다(항목마다 고유 id 부여).

### R5. 새로고침 후 유지
- 추가·완료 토글·삭제가 일어날 때마다 전체 목록을 `localStorage`에 저장한다.
- 페이지를 열 때 `localStorage`에서 목록을 불러와 표시한다.
- 저장 데이터가 없거나 JSON 파싱에 실패하면 빈 목록으로 시작하고, 에러로 화면이 깨지지 않게 한다.
- 저장 형식: 키 `todos`, 값 `[{ "id": string, "text": string, "done": boolean }]`

### 기술 제약
- 순수 HTML, CSS, JavaScript만 사용한다. 외부 라이브러리, CDN, 디자인 프레임워크는 쓰지 않는다.
- 빌드 도구나 로컬 서버 없이 `index.html`을 더블클릭해서(`file://`) 열면 실행되어야 한다.
- 파일 구성: `index.html`, `style.css`, `app.js` 3개로 분리한다.
- 대상 브라우저: 최신 Chrome / Edge

## 범위

### 포함 (In Scope)
- 할 일 추가(버튼 / Enter), 빈 입력·공백 입력 차단, trim 처리
- 목록 표시와 빈 목록 안내 문구
- 완료 체크/해제
- 개별 삭제
- localStorage 저장과 복원

### 제외 (Out of Scope)
- 로그인·회원 기능
- 서버, DB, 외부 API
- 마감일, 카테고리, 태그, 우선순위
- 디자인 프레임워크(Bootstrap, Tailwind 등)
- 할 일 텍스트 수정, 드래그 정렬, 필터(전체/진행/완료), 완료 항목 일괄 삭제, 실행 취소

## 성공 지표

모든 항목은 Chrome에서 `index.html`을 직접 열어 확인한다. "초기 상태"는 개발자도구 → Application → Local Storage에서 `todos` 키를 삭제한 뒤 새로고침한 상태를 말한다.

| # | 입력 / 조작 | 기대 결과 |
|---|---|---|
| AC-01 | 초기 상태에서 `index.html` 열기 | 빈 목록과 "할 일이 없습니다" 문구가 보이고, 콘솔 에러가 없다 |
| AC-02 | `우유 사기` 입력 → 추가 버튼 클릭 | 목록에 "우유 사기" 1개가 표시되고, 입력창이 비워지고, 안내 문구가 사라진다 |
| AC-03 | `빵 사기` 입력 → Enter | "빵 사기"가 "우유 사기" 아래에 추가된다 |
| AC-04 | 입력창을 비운 채 추가 버튼 클릭 | 목록 변화 없음 |
| AC-05 | 입력창을 비운 채 Enter | 목록 변화 없음 |
| AC-06 | 스페이스 3칸만 입력 → 추가 | 목록 변화 없음 |
| AC-07 | `  운동하기  ` (앞뒤 공백) 입력 → 추가 | 앞뒤 공백 없이 "운동하기"로 추가된다 |
| AC-08 | "우유 사기"의 체크박스 클릭 | 체크 표시가 되고 텍스트에 취소선이 생긴다 |
| AC-09 | AC-08에서 같은 체크박스를 다시 클릭 | 체크와 취소선이 해제된다 |
| AC-10 | "빵 사기"의 삭제 버튼 클릭 | "빵 사기"만 사라지고 나머지 항목은 그대로다 |
| AC-11 | 항목 3개를 추가하고 2번째를 완료 체크 → F5 새로고침 | 3개가 같은 순서로 보이고, 2번째만 완료 상태다 |
| AC-12 | 항목 1개 삭제 → F5 새로고침 | 삭제한 항목은 다시 나타나지 않는다 |
| AC-13 | 브라우저 탭을 닫고 `index.html`을 다시 열기 | 닫기 직전 목록과 완료 상태가 그대로 보인다 |
| AC-14 | 모든 항목 삭제 | "할 일이 없습니다" 문구가 다시 보인다 |
| AC-15 | `같은 일`을 두 번 추가 → 첫 번째 것의 삭제 클릭 | 두 번째 "같은 일" 1개만 남는다 |
| AC-16 | `<b>굵게</b>` 입력 → 추가 | 굵은 글씨가 아니라 `<b>굵게</b>` 문자 그대로 표시된다 |
| AC-17 | 개발자도구에서 `todos` 값을 `abc`로 바꿈 → 새로고침 | 빈 목록으로 정상 표시되고, 앱이 멈추지 않는다 |
| AC-18 | 개발자도구 Network 탭을 연 상태로 새로고침 | `index.html`, `style.css`, `app.js` 외에 외부 요청이 없다 |

## 확인이 필요한 가정
사용자가 세부 결정을 위임하여 아래와 같이 정했다. 필요하면 구현 전에 바꿀 수 있다.
1. 새 항목은 목록 맨 아래에 추가한다.
2. 빈 입력·공백 입력은 경고나 안내 문구 없이 무시한다.
3. 삭제 시 확인창을 띄우지 않는다.
4. 완료한 항목도 제자리에 둔다.
5. 텍스트 수정 기능은 이번 범위에서 제외한다.
6. 파일은 `index.html` / `style.css` / `app.js` 3개로 나눈다.
